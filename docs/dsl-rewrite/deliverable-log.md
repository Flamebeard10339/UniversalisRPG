**Time model detail (confirmed 2026-07-17):** simulated time is a first-class currency for BOTH play and authoring. Actions carry a time value (0..inf, 0 default = instant). A `/wait <s>` command is available everywhere. A global time multiplier (2x/10x) exists for debugging. Agent play runs an "agent mode" decoupled from the wall clock: wait-until-a-command-finishes, and measure the SIMULATED time an agent took. Determinism is non-negotiable because authoring agents measure whether a quest fits a time budget.

**NORTH STAR beyond this branch:** authoring agents that build quests/features given a **time budget**, where any text read counts against the budget (average reading speed). Each quest may have side tangents up to 3x the budget for a curious player/agent but must be completable within the base budget. End state: spawn dozens of agents to build the world into a rich tapestry of interlocking quests. This is WHY the DSL + deterministic simulated-time + agent play protocol matter.

**Three-layer play model (ratified 2026-07-17):** (L1) **agent CLI** — actions instant in real time, sim-time accrues as a resource; used for debugging (instant) and measuring an authored section's length (final `state.time` = the real playtime a human would spend). (L2) **human CLI / true text-adventure** — actions trigger transitionary progress states (travelling, cooking, fighting), driven by an update loop pushing the time driver forward every N ms. (L3) **RPG GUI** — thin graphical layer exposing actions/resources/locations/items as buttons. HARD CAPABILITY BOUNDARY between L1 and L2: L1 needs nothing new (chunk 2 delivered it); L2 is blocked on a runtime concept that does NOT exist yet — **spannable/transitionary actions** (`useAction` is currently atomic: applies all results + jumps `state.time` in one sync call, runtime.ts:327-329).
