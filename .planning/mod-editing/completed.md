- Extended the DSL/compiler along the way, each with grammar-doc updates + tests: item `title:`/`description:`/`maxQuantity:`; location `title:`/`description:`/`exhausted:`; entity `title:`; `# advanced` `locale` (fills locale gaps without clobbering, `??=`) and `data-updates` (raw cross-module patches/removals) escape hatches; `requires: tag:x` / `requires: equipped tag:x` (item-tag/equipped-item-tag conditions); `relocate:` and `set spawn:` tags (unconditional move / respawn-point change, for portals/ladders/tunnels outside the grid-wall pattern); `max: N` tag (arbitrary `maxCompletions`, without `once`'s auto-visibility guard — for a repeatable-but-capped action like a training dummy).
- Fixed a genuine pre-existing validator bug found while porting `tutorial-island-survival`: `knownStateVariables()` in `src/game/validators.ts` only recognized `action-completions:` ids from top-level `bundle.actions`, never from `bundle.entities[].actions` or `bundle.items[].actions` — any entity/item action relying on its own completion count (e.g. bare `once` with no `set:` flag) spuriously failed validation.
- Added DSL sugar for `# stat <id>`, `# skill <id>`, `# flags` (bulk, one flag per line), and `droptable:`/`# droptable <id>` (nested independent/dependent reward tables, referenced by id) — the `max: N` tag proved out earlier; a compiler test reproduces `base-core`'s original hand-written 4-level nested goblin drop table exactly, byte-for-byte in structure. `tutorial-island-foundation.md` now uses the new stat/skill/flags sugar instead of a raw `# advanced` block (only a one-line `modulePack.tutorial-island.title` locale entry remains in `# advanced`, since module-pack titles have no DSL section of their own).
- Fixed a real UI bug the aggressive `base-core` content cull surfaced: `App.tsx` blocked the *entire* app — including the Edit tab — whenever `playState` failed to initialize (e.g. every tutorial-island module cascade-disabled by one broken dependency, leaving no starting location). Now, if `contributionMode` is on and `bundle` loaded but `playState` didn't, the app falls through to a minimal shell hosting just the Edit tab instead of a hard error screen — the Edit tab only needs `bundle`/the draft, not a live game session, so it's exactly the tool needed to debug the broken content.
- Cleaned up real breakage left by the `base-core` content cull (crossroads/emberwood/old-quarry and `wayside-supplies`/`tutorial-island-reset` removed): `universe.json`'s `modules` list still referenced the two deleted module ids; `tutorial-island-foundation.md` still depended on the deleted `tutorial-island-reset`; `base-core.json`'s `health` resource still listed the deleted `emberleaf` item in `preserve.inventoryIds`; `tutorial-island-mining.md` had an unused `bronze-spear` item and, after `tutorial-island-combat.md`'s cross-module patch connecting `forge-table` → the rat cage was dropped in favor of the ladder-style pattern, no replacement was ever added (rat cage was unreachable) — restored as a plain `relocate:` action on `forge-table`. `tutorial-island-mine`'s new `ladder` entity pushed the location to 6 entities against the engine's 5-per-location display cap — merged into the existing `mine-tunnel` entity instead of a separate one. `health`/`attack`/`defense`/`regeneration` stats+skills were moved entirely into `tutorial-island-foundation.md`, breaking `base-core`'s own resources/interactionType (which reference those stats) when `base-core` loads without foundation — moved back into `base-core.json` (which already had unused locale entries for exactly these, confirming they belonged there), leaving foundation with only its own tutorial-specific stats (mining/smithing/fishing/cooking/thieving/movement-speed). Updated four pre-existing tests (`merge-contribution-issue.test.mjs`, `loader.test.ts`, `modEditService.test.ts`) that hard-coded assumptions from the old, larger `base-core` (patches against deleted `crossroads`/`emberwood`/`old-quarry`, `wayside-supplies` enabled) to use content that still exists.
